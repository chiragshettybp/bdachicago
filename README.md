# Chicago 311 Service Request Analytics

Big Data Analytics project using the City of Chicago [311 Service Requests
dataset](https://data.cityofchicago.org/Service-Requests/311-Service-Requests/v6vf-nfxy/about_data).
Requests created after the launch of the new 311 system on 12/18/2018 (plus some
legacy records flagged in `LEGACY_RECORD`).

Real example request types, departments, addresses, and ready-to-use dashboard
URLs are collected in [EXAMPLES.md](EXAMPLES.md).

The project validates the source CSV, converts it to daily per-request-type
records, and compares annual summaries per service request type using Python,
MongoDB, Hadoop MapReduce, Pig, and Hive. A two-page Flask dashboard lets users
inspect a request type's year-by-year profile or rank request types by a
selected year.

## Where to save the dataset CSV

Download the CSV export of the dataset and save it here:

```text
data/source/311_Service_Requests.csv
```

Create the `data/source` folder if it does not exist. Any filename works — pass
its path to `--input` — but `data/source/` is the conventional location and is
already excluded from Git. A small sample file for a quick test is available at
`data/source/sample_311.csv` (generated by `scripts/make_sample_csv.py`).

## Quick start (Python, Windows or Linux)

Use Python 3.11 or newer. Install dependencies:

```powershell
python -m pip install -r requirements.txt
```

Produce annual summaries and open the dashboard:

```powershell
python -m service_requests prepare --input "data/source/311_Service_Requests.csv" --output "data/prepared/service_requests"
python -m service_requests analyze --daily "data/prepared/service_requests/daily.tsv" --output "results/service_requests"
python -m service_requests dashboard --results "results/service_requests"
```

Open `http://127.0.0.1:5000` in a browser.

Page 3 of the dashboard (`/?page=examples`) lists every real example request
type as a clickable card plus year-ranking links for all metrics.

## Example requests to try

These are real service request type names from the Chicago dataset. Paste them
into Page 1 or use the URLs directly:

| Example URL | What it shows |
|---|---|
| [`/?client_id=Pothole+in+Street+Complaint`](http://127.0.0.1:5000/?client_id=Pothole+in+Street+Complaint) | Pothole complaints by year |
| [`/?client_id=Rodent+Baiting%2FRat+Complaint`](http://127.0.0.1:5000/?client_id=Rodent+Baiting%2FRat+Complaint) | Rat complaints by year |
| [`/?client_id=311+INFORMATION+ONLY+CALL`](http://127.0.0.1:5000/?client_id=311+INFORMATION+ONLY+CALL) | Information-only calls (the 311 Center's own records) |
| [`/?client_id=Aircraft+Noise+Complaint`](http://127.0.0.1:5000/?client_id=Aircraft+Noise+Complaint) | O'Hare aircraft noise complaints |
| [`/?page=year&year=2024&metric=requests&top_k=10`](http://127.0.0.1:5000/?page=year&year=2024&metric=requests&top_k=10) | 2024 ranking by total requests |
| [`/?page=year&year=2024&metric=avg_resolution_days&top_k=13`](http://127.0.0.1:5000/?page=year&year=2024&metric=avg_resolution_days&top_k=13) | 2024 ranking by average resolution time |

Other real type names in the sample: `Graffiti Removal Request`,
`Street Light Out Complaint`, `Garbage Cart Maintenance`,
`Abandoned Vehicle Complaint`, `Tree Debris Clean-Up Request`,
`Traffic Signal Out Complaint`, `Building Violation`,
`Water Lead Test Kit Request`, `Dead Animal Pick-Up Request`.

The sample CSV mirrors real dataset patterns: information-only calls are
recorded at the 311 Center address (`2111 W Lexington ST`), aircraft noise at
O'Hare (`10510 W ZEMKE RD`), potholes peak in spring, rat complaints in summer,
and tree debris in fall.

Page 1 accepts a service request type such as `Pothole in Street Complaint`,
shows annual metrics, and lets the user select the pie-chart basis: Total
requests, Mean requests/day, Max daily requests, or Avg resolution days. A
separate bar comparison identifies highest/lowest years by total requests.
Page 2 accepts a year, ranking metric, and Top K, then highlights the
highest and lowest request types by that metric and lists the top K.

Pie slices compare a single selected metric across years. The four measures are
not combined into one pie because counts and days use different units.

## Optional MongoDB

Start a local MongoDB service, then run:

```powershell
python -m service_requests mongo --daily "data/prepared/service_requests/daily.tsv" --database service_requests_311
```

The MongoDB command imports daily request-type records and aggregates annual
totals, mean daily requests, maximum daily requests, and average resolution
days.

## Hadoop, Pig, and Hive

The distributed toolchain is set up separately; see `infra/compose.yaml`.
Python preparation writes `daily.tsv`; Hadoop Streaming, Pig, and Hive consume
that same normalized data. The Mapper/Reducer can also be cross-checked locally
by the `analyze` command.

The large source file, generated `data/`, and `results/` are local and excluded
from Git. Use a new output directory for every preparation or analysis run.
